# DeveloperHCR v2.2.0-beta — Account, Subscription & Control Improvements

## Added
- Preconfigured Owner account for this release using the credentials supplied by the project owner.
- Owner credentials remain changeable from Account/Owner controls; passwords are stored only as salted PBKDF2 hashes.
- Duplicate usernames remain blocked case-insensitively.
- Paid subscription request workflow:
  - User selects a plan.
  - A pending request is stored locally.
  - If Owner configured a WhatsApp Group/Channel in Settings → Support, the app opens that link immediately after the request.
  - User confirmation/payment discussion remains in WhatsApp.
  - Owner or Admin manually approves/rejects the pending request in the dashboard.
  - Paid access is activated only after approval; no fake payment success is generated.
- Admin Dashboard now shows the full user list (username, role, status, plan and latest subscription request status).
- Admin Dashboard can approve/reject subscription requests.
- Owner Dashboard also shows and manages subscription requests.
- Subscription request history is visible to the requesting user.
- Subscription workflow is additive and uses a new `subscription_requests` SQLite table.

## Preserved
All existing v2.1 application modules, AI/Jarvis/Kausar, Store, Browser, Games, Friends Only, Practice Trading, EXE/Wine, Update Center, Settings, Control Panel, landscape desktop, startup/skip fixes, local-first data and privacy boundaries are preserved.

## Privacy / payment honesty
- The app does not claim that a WhatsApp message itself proves payment.
- Payment verification remains a human Owner/Admin approval step unless a real payment provider is connected later.
- Private/E2EE privacy rules are unchanged.
