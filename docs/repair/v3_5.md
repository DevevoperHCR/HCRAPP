# DeveloperHCR v3.5 — Auth, Store & Access Fix

## Authentication
- One login screen only.
- The server detects NORMAL_USER, ADMIN, or OWNER from the supplied credentials.
- No User/Admin/Owner mode buttons.
- Packaged Owner account remains preconfigured.
- Normal-user signup is direct and active immediately; no Owner/Admin approval.
- Duplicate usernames are case-insensitive.
- Login errors are explicit (missing username/password, unknown username, wrong password, disabled account).
- Owner/Admin credentials are not exposed in the UI as separate login paths.

## Store / access
- HCR Store lists the full built-in app catalog.
- Apps unavailable to the current user remain visible in the Store but are disabled/locked.
- Launcher only shows apps currently usable by the signed-in user.
- Owner/Admin retain all features.
- Paid feature gates continue to use the subscription/access feature API.

## Agreement / Admin Sync
- Data Agreement is shown for signup/first required agreement.
- Admin Sync defaults ON for non-private diagnostics/approved telemetry.
- Passwords, tokens, private chats, search history and file contents are excluded from the documented sync path.
- Private modes disable sync of private content.

- Owner login endpoint tested successfully.
- Wrong-password and missing-field errors tested.
- Temporary Admin role login tested successfully; temporary test account removed from release DB.
- Direct normal-user signup tested; duplicate username tested.
- Python/JS syntax checks passed.
- `PYTHONPATH=. pytest -q`: 11 passed.
