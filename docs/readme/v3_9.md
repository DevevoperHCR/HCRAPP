# DeveloperHCR v3.9 — Startup & Login UI Fix

## Startup
- The startup splash is intentionally lightweight and lasts 5 seconds.
- It shows only the DeveloperHCR logo, a fake loading bar, status and a 5→1 countdown.
- Skip immediately opens the login screen.
- No filesystem scan or AI/network check blocks startup.

## Login
- The login screen is intentionally minimal: logo, Username, Password and Start.
- No New User button, Quick Unlock button, agreement button or explanatory text is shown on the login screen.
- Login errors appear only when an actual error occurs.
- Owner/Admin role is determined by the server from the supplied credentials.
- The existing local database remains authoritative; credentials are not hard-coded into the browser UI.
- Enter key also submits the login form.

## Launcher
- On the first launcher run, if no ADMIN account exists, `launcher.py` asks for an Admin username and password.
- The password is entered interactively and stored only as a salted PBKDF2 hash in the local SQLite database.
- Once an Admin exists, the launcher does not ask again.

## Compatibility
- The emergency login fallback avoids `async` syntax so older embedded/mobile JavaScript engines cannot fail with `async is not defined`.
- The desktop is not gated by optional background initialization after successful login.

The visible login UI intentionally contains no New User, Quick Unlock, agreement, or explanatory copy; those functions remain available in their appropriate application/settings areas.
